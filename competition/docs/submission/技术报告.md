# R³E-AIC 技术报告提纲

## 一、作品概述

R³E-AIC 是面向 RTL 功能语义缺陷的智能纠错系统。系统目标是把“发现缺陷、提出修复、真实验证、吸收安全经验”连接成一条可追溯链路。

## 二、需求分析

RTL 的编译成功不能证明状态机、时序控制和 bit-level dataflow 正确。工程人员仍需依赖波形、testbench 和回归定位问题。正式提交前，需求调研和用户反馈应以可公开的原始材料补齐；本代码包不把未提供的反馈写成既成事实。

## 三、AI 技术工具选择与运用

大语言模型负责诊断建议和候选 RTL 提案；R³E candidate portfolio 组织 generic、temporal、control、dataflow 多专家视角。模型没有 oracle、排序或晋级权限。

## 四、项目实施

Competition API 通过 service facade 调用 R³E Core。验证链包含 Parse、Compile、Simulation、R³E differential Oracle、Yosys structural/formal-sanity 和重复回归。Live provider 使用严格 JSON、固定候选预算和环境变量凭据；Demo 默认使用冻结参考候选回放，明确不作为模型效果。

## 五、应用成效

正式 headline 数字必须来自 `competition/results/frozen/metrics.json`，并绑定 commit、数据 manifest、model/provider、seed、budget、verifier、Icarus/Yosys 版本和结果 hash。本仓库当前只冻结三个真实 EDA 可复现演示案例，不预填未经审计的 benchmark 增益。

## 六、总结与展望

系统展示了“模型提案、EDA 判定”的工程闭环。后续可在独立授权下冻结真实 provider benchmark、非目标回归和策略/经验演化结果，并补充正式视频、PPT、用户反馈及佐证材料。
