# R³E：自进化RTL智能纠错系统

## 1. 作品定位

R³E 是面向 RTL 功能语义缺陷的智能纠错系统。比赛软件版本为
`R³E-AIC Competition M2`。系统的核心边界是：模型或 provider 只提出候选，
runner 负责运行时证据、候选分配、AST/Scope Authority、EDA 验证、选择和证据
记录。

## 2. M2 主链

```text
Buggy RTL + Testbench
  → Icarus runtime mismatch
  → Failure Descriptor v2
  → R³E descriptor router
  → R³E Blue Candidate Portfolio
  → AST / interface / forbidden-behavior Scope Gate
  → Parse → Compile → Simulation → Functional Oracle
  → Yosys Structural Check → Repeatability Check
  → candidate receipt / accept / reject
```

`competition/services/diagnosis_service.py` 从 oracle mismatch、结构化 oracle
证据和当前 buggy RTL 上下文构造 descriptor；路由使用
`configs/blue/descriptor_router_v1.json`，不读取 case 的人工 defect annotation
来决定 lens。`competition/services/repair_service.py` 只负责 adapter，实际
portfolio allocation、provider receipt、semantic signature 和 deterministic
selection 由 `r3e/blue/portfolio/` 执行。

## 3. 三个演示案例

Counter、FSM、Shift 均来自公开 CirFix 输入，并保留 case hash、buggy/reference/
testbench hash。Guided 模式从 buggy RTL 应用 checked-in 的最小 patch，reference
RTL 永远只承担 oracle authority，不作为候选源。三个候选都经过同一组 gate，
因此演示不会把 compile pass 或 reference copy 当成修复证明。

## 4. 验证术语边界

| 术语 | 代码实际含义 |
|---|---|
| Functional Oracle | Icarus differential `oracle_gate.judge` |
| Structural Check | Yosys `read_verilog`、`hierarchy`、`proc`、`opt`、`check` |
| Repeatability Check | 同一 candidate 和 testbench 的再次运行比较 |
| Non-target Regression | 只有存在 disjoint replay artifact 时才可使用；当前演示不宣称 |
| Formal Proof | 当前比赛版不宣称；Structural Check 不是 property proof |
| Multi-expert Repair | R³E Blue Candidate Portfolio 的真实 lens allocation |
| Automatic Diagnosis | runtime-generated Failure Descriptor，不是 case annotation |
| Evolution | 只有 frozen evolution artifact 存在时 UI 才可用 |
| Memory | 只有 activation audit、replay 和 regression 证据存在时 UI 才可用 |

## 5. 证据与复现

`competition/results/frozen/` 分为 `demo/`、`benchmark/`、`evolution/` 和
`memory/` 四条证据链。当前 benchmark、evolution、memory 的 manifest 明确为
`available: false`，不填充零值或未审计数字。live raw run 只能在具备干净
workspace、commit、provider/model/version、seed、candidate budget、case hash、
toolchain、result hash 后由 `freeze_results.py` 写入 demo evidence。

复现命令：

```bash
./competition/scripts/setup.sh
./competition/scripts/run_demo.sh
./competition/scripts/verify_benchmark_inputs.sh
python3 competition/scripts/check_anonymization.py
python3 scripts/check_release.py
```

真实 provider 运行需要显式使用 `--mode live`，并由用户单独提供凭据；仓库不
包含模型响应、凭据、运行日志或 machine-specific manifest。
